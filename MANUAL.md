# sandbox — руководство

[English](MANUAL.en.md) · [Краткий выбор режима](README.md)

Это подробный справочник по Linux/WSL и устройству изоляции. Для первого запуска
достаточно README.md и TUI.md; для Windows начните с WINDOWS.md, а для варианта
отдельной учётной записи — с WINDOWS_NATIVE.md. Разделы 5–9 объясняют границы
защиты, разделы 10–12 — диагностику и проверки.

Песочница для ИИ-помощников (Codex, Claude Code и др.): агент работает в одной рабочей папке
`workspaces/<проект>`, а видимость файлов, сети, процессов и сведений о хосте ограничивают механизмы ОС.
Краткая версия — [README.md](README.md); терминальный рабочий стол — [TUI.md](TUI.md);
Windows — [WINDOWS.md](WINDOWS.md); аудиты — [SECURITY_REPORT.md](SECURITY_REPORT.md).

## 1. Что это и от чего защищает

Модель угроз: агент — процесс, которым управляет языковая модель. Он может ошибаться, выполнять вредные
команды из чужого кода или подвергнуться prompt injection. Защита рассчитана на то, чтобы такой агент:

- не читал и не менял файлы вне рабочей папки (ключи, браузерные профили, другие проекты);
- не видел и не трогал процессы, пользователей, сеть и службы хоста;
- не узнавал лишнего о хосте (оборудование, имя пользователя, пути, часовой пояс);
- не мог запустить свою команду на хосте через файлы проекта (хуки git, задачи IDE и т. п.);
- не исчерпал память и число процессов хоста.

Слои действуют одновременно: пространства имён (user, pid, net, ipc, uts, cgroup) -> сброс capabilities и
`no_new_privs` -> seccomp (`seccomp.py`) -> Landlock и чистое окружение (`inner.py`) -> нейтральная среда
(`neutral.py`) -> защита исполняемых на хосте файлов (`guard.py`) -> лимиты cgroup/RLIMIT. Прокси с белым
списком доменов работает на хосте. Это защита ядра Linux, **не виртуальная машина** (границы — в разделе 9).

## 2. Платформы и требования

| Платформа | Режим | Проверено |
|---|---|---|
| Linux x86_64 и aarch64 | bubblewrap, `./install.sh` | Arch (ядро 7.2): 91 тест, `selftest` 33/33 на трёх профилях; реальные `codex --version` и `claude --version` внутри |
| Windows 10/11 + WSL2 | то же внутри WSL2 | не проверено на Windows |
| Windows + Docker Desktop (Linux containers) | контейнер без сети + прокси | не проверено на Windows |
| Windows x64 без WSL и Docker | `--backend user`: отдельная учётная запись, ACL/WFP; см. WINDOWS_NATIVE.md | unit-тесты; runtime Windows не проверен |
| WSL1, NixOS, Guix, macOS, BSD, 32-бит, riscv64, ppc64le, s390x | не поддерживается | — |

**Требования на Linux.** Ядро с непривилегированными user namespaces (Landlock 5.13+ необязателен, но желателен);
bubblewrap (свежая версия, проверено на 0.13: ключи `--disable-userns`, `--ro-bind-data`, `--size`; в старых их нет и часть
защит слабее — `sandbox check` покажет, каких именно); Python **3.8+** на хосте (профили читает `tomllib`, `tomli` или встроенный
`tomlmini.py`) и `/usr/bin/python3` (он запускается первым внутри песочницы); обычный пользователь, не root;
`systemd --user` — для лимита памяти (необязателен).

### 2.1. Дистрибутивы

Команда установки пакетов подставляется автоматически: `./install.sh --install-deps`.

| Семейство | Пакеты | Особенности |
|---|---|---|
| Arch, Manjaro, EndeavourOS | `sudo pacman -S bubblewrap python` | Проверено. Claude Code из пакета лежит в `/opt/claude-code` — профиль `claude` монтирует его |
| Debian 12+, Ubuntu 22.04+, Mint, Pop!_OS, Kali | `sudo apt install bubblewrap python3` | Ubuntu 22.04: Python 3.10 — работает через встроенный разбор TOML. Ubuntu 23.10+/24.04: AppArmor ограничивает user namespaces — `./install.sh --fix-apparmor`. Debian со значением `kernel.unprivileged_userns_clone=0`: `sudo sysctl kernel.unprivileged_userns_clone=1` |
| Fedora, RHEL 8/9, CentOS Stream, Rocky, Alma | `sudo dnf install bubblewrap python3` | RHEL/Rocky 9: Python 3.9 — работает через `tomlmini.py`. Fedora Silverblue/Kinoite/Bazzite: `/home` — ссылка на `/var/home`, поддерживается; bubblewrap обычно уже есть, иначе `rpm-ostree install bubblewrap`. Для TLS монтируется `/etc/crypto-policies` |
| openSUSE Leap/Tumbleweed, SLE | `sudo zypper install bubblewrap python3` | Leap 15: системный Python 3.6 — поставьте `python311` и укажите `./install.sh --python python3.11`. Сертификаты лежат в `/var/lib/ca-certificates` — монтируются |
| Alpine | `apk add bubblewrap python3` | musl и busybox; установщик — POSIX `sh`, bash не нужен |
| Void | `xbps-install bubblewrap python3` | |
| Gentoo | `emerge sys-apps/bubblewrap dev-lang/python` | |
| Steam Deck / SteamOS, Chromebook (Linux) | как у основы (Arch / Debian) | bubblewrap на SteamOS есть как зависимость flatpak; корень только для чтения — ставьте в `$HOME` |
| NixOS, Guix | не поддерживаются | нет `/usr/bin/python3` и привычной раскладки `/usr` |

Только Arch проверен на практике; остальные строки основаны на документации дистрибутивов. Если на вашем
дистрибутиве что-то не так — `sandbox check` печатает причину и подсказку, а раздел 10 разбирает типичные случаи.

### 2.2. Особые среды

- **WSL2** — поддерживается как обычный Linux. Для лимитов памяти включите systemd (`[boot] systemd=true` в
  `/etc/wsl.conf`). Для строгой изоляции лучше отдельный дистрибутив с `[interop] enabled=false` и
  `[automount] enabled=false` (см. [WINDOWS.md](WINDOWS.md)); `sandbox check` предупредит, если они включены.
- **WSL1** — namespaces не поддерживаются: `wsl --set-version ДИСТРИБУТИВ 2`.
- **Внутри контейнера (Docker/Podman) и CI** — bubblewrap обычно не может создать user namespace; нужны
  ослабленные профили seccomp/AppArmor контейнера. Надёжнее запускать песочницу на хосте или в ВМ.
- **Immutable-системы** — код и данные живут в `$HOME`, системных изменений нет.

## 3. Установка

### 3.1. Linux и WSL2

    ./install.sh                  # из распакованной папки; файлы остаются на месте или копируются в ~/sandbox

Установщик (POSIX `sh`) определяет систему, проверяет требования, при необходимости ставит пакеты (только с
`--install-deps` и вашего подтверждения), создаёт каталоги, ставит команду `sandbox`, запускает `sandbox check`
и `sandbox selftest`. Ошибка любой проверки даёт код выхода 1. Повторный запуск из новой копии **обновляет код**
и сохраняет профили (изменённый вами профиль не перезаписывается — новая версия рядом, `*.new`), рабочие папки,
HOME агентов, журналы и состояние.

| Параметр | Действие |
|---|---|
| `--prefix КАТАЛОГ`, `--bin-dir КАТАЛОГ` | куда ставить песочницу (по умолчанию `~/sandbox`) и команду (`~/.local/bin`); также `SANDBOX_PREFIX`, `SANDBOX_BIN_DIR` |
| `--no-link`, `--add-path` | не создавать команду; либо дописать `PATH` в `~/.profile` |
| `--python КОМАНДА` | интерпретатор для команды `sandbox` (например `python3.12`): создаётся обёртка |
| `--profiles default,codex` | какие встроенные профили устанавливать; `--force-profiles` заменяет изменённые |
| `--check` | только диагностика среды, ничего не меняет |
| `--install-deps` | поставить bubblewrap и Python пакетным менеджером (`sudo`, с вопросом) |
| `--fix-apparmor` | Ubuntu 24.04+: профиль AppArmor, разрешающий user namespaces **только для bwrap** (показывает файл, спрашивает) |
| `--no-check`, `--no-selftest`, `--selftest-all` | пропустить проверку окружения или самопроверку; проверить все профили |
| `--uninstall` [`--purge`] | удалить команду; с `--purge` — и каталог установки (рабочие папки и токены агентов!) |
| `-y`, `--dry-run` | без вопросов; только показать действия |

Примеры: `./install.sh --prefix /opt/sandbox --bin-dir /usr/local/bin` (каталоги должны быть доступны вам на запись:
`sudo mkdir /opt/sandbox && sudo chown $USER /opt/sandbox`; сам установщик не работает от root), `./install.sh --check`, `./install.sh --install-deps -y`, `./install.sh --dry-run`.
Скрипт нужно запускать из распакованной папки, а не через `curl | sh`.

### 3.2. Что лежит в каталоге

| Путь | Назначение |
|---|---|
| `sandbox.py`, `inner.py`, `seccomp.py`, `probe.py` | запуск и сборка bwrap; первый процесс внутри; фильтр syscalls; атаки для `selftest` |
| `transport.py` | ограниченный по памяти и потокам мост TCP/Unix, тайм-ауты и проверка готовности прокси |
| `neutral.py`, `guard.py`, `tomlmini.py` | нейтральная среда; защита исполняемых на хосте файлов; разбор TOML для Python < 3.11 |
| `ui.py`, `tui.py`, `textual_tui.py`, `requirements-tui.txt` | оформление CLI и виджетный сезонный TUI на Textual/Rich (необязательные зависимости) |
| `skills.py`, `agent-skills/` | подготовка текстовых навыков в копии проекта для Claude/Codex |
| `profiles/*.toml` | профили; `workspaces/` — проекты агентов; `home/` — их постоянные `$HOME` |
| `state/`, `logs/` | подтверждения запуска, временные файлы; журнал прокси и запусков (`sandbox log`) |
| `AGENT_POLICY.md`, `AGENTS.md`, `tests/` | правила агента (раздел 11); правила работы над кодом; регрессионные тесты |

### 3.3. Windows

В терминале Linux команда `sandbox` без параметров открывает TUI, также доступно
`sandbox tui`. На Windows `start.cmd` открывает TUI, `start.cmd gui` — графическое окно.
Проверка модулей при загрузке не заменяет `sandbox selftest`; порядок работы — [TUI.md](TUI.md).

Третий режим `--backend user` создаёт пользователя Windows и привязывает прокси к выбранному адаптеру.
Он не скрывает интерфейсы/процессы хоста; см. [WINDOWS_NATIVE.md](WINDOWS_NATIVE.md).

Подробно — [WINDOWS.md](WINDOWS.md): `install.ps1 -Check` покажет, что доступно (WSL2, Docker), и установит нужный
режим. Виджетный TUI требует отдельной установки зависимостей из `requirements-tui.txt`; без них остаётся компактный встроенный режим. Без WSL2/Docker можно явно выбрать `-Backend user`: это более слабая ACL/WFP-граница, описанная отдельно в WINDOWS_NATIVE.md.

## 4. Быстрый старт и команды

    sandbox new myproj                         # пустая рабочая папка
    sandbox new myproj --copy ~/code/myproj    # или копия проекта (без .env, ключей и учётных данных в URL git)
    sandbox run codex myproj                   # Codex;   sandbox run claude myproj — Claude Code
    sandbox shell default myproj               # оболочка внутри: посмотреть, что видит агент
    sandbox audit myproj                       # файлы проекта, которые хост выполнит сам

Из `workspaces/myproj` имя можно не указывать. Рабочая папка — обычный каталог в `workspaces`, не ссылка.
`new` не копирует поверх существующего каталога, пропускает `.env*`, `*.pem`, `*.key`, `id_*`, `.npmrc`,
`.pypirc`, `.netrc`, `.git-credentials`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `*.kdbx`, `credentials.json`,
`service-account*.json`, `terraform.tfstate*` (печатает число пропущенных) и вырезает `user:token@` из URL в
`.git/config` копии. Это не универсальный поиск секретов. Копирование каталогов вроде `~`, диска Windows
(`/mnt/c`), `C:\Users\<вы>`, `AppData`, `.ssh` отклоняется.

Первый вход в агента — **внутри** песочницы (логин или `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` через `env_pass`).
Токены хранятся в `home/<профиль>/` и не пересекаются с настоящими `~/.codex` и `~/.claude`.

| Команда | Назначение |
|---|---|
| `sandbox new ИМЯ [--copy ПУТЬ]`, `sandbox ws` | создать рабочую папку; список |
| `sandbox run [ПРОФИЛЬ] [ИМЯ] [-- команда]`, `sandbox shell [ПРОФИЛЬ] [ИМЯ]` | запуск профиля; `bash` внутри |
| `sandbox list`, `sandbox show ПРОФИЛЬ` | профили |
| `sandbox check` | окружение: платформа, bwrap и его возможности, ядро, WSL, подсказки при отказе |
| `sandbox selftest [ПРОФИЛЬ]` | 33 атаки изнутри на собственные фикстуры; не собирает сведений о хосте |
| `sandbox audit [ИМЯ]` | опасные для хоста файлы в рабочей папке; код выхода 1, если найдены |
| `sandbox tui`, `sandbox skills ИМЯ` | терминальный рабочий стол; подготовка двух навыков для Claude и Codex в выбранной копии |
| `sandbox log [-n N]` | журнал за сегодня (значения от агента экранируются) |

Флаги `run`/`shell`: `--access read|edit` (проект только для чтения или с записью), `--ro ПУТЬ`, `--rw ПУТЬ` (только
внутри `workspaces`), `--net off|allowlist`, `--domain D`, `--env ИМЯ`, `-y`, `--dry-run`, `--allow-outside` и
`--allow-sensitive` (снижают защиту). Явный `--access read` отклоняет `rw`,
перекрывающие проект. **Ctrl-C** завершает песочницу (агенты с экранным интерфейсом получают Ctrl-C как нажатие
клавиши); не ответила за 5 секунд или второй Ctrl-C — принудительно. Запуск от root и на не-Linux отклоняется.

## 5. Что видит агент

| Видит | Не видит |
|---|---|
| рабочую папку проекта (чтение и запись, либо только чтение); в нейтральной среде это `/workspace` | остальные файлы, настоящий домашний каталог, `~/.ssh`, `~/.aws`, браузерные профили |
| свой постоянный `$HOME` (`home/<профиль>`; в нейтральной среде `/home/user`) | другие проекты, `~/sandbox` (профили, журналы, состояние), `/sys`, `/var`, `/run/user` |
| `/usr` и несколько файлов `/etc` (сертификаты, nsswitch) только для чтения; синтетические passwd/group/hosts | процессы и пользователей хоста, сеть хоста, службы на localhost, D-Bus/X11 |
| `/tmp` (tmpfs), минимальные устройства; каталоги инструментов из `ro` профиля | секреты в окружении хоста: окружение пустое, кроме базового набора, `env_pass` и `env_set` |

### 5.1. Нейтральная среда (`neutral = true`, во всех встроенных профилях)

Решает требование «агент работает только в каталоге и не показывает других свойств хоста». Подменяется:

- `/proc/cpuinfo` (одна «Virtual CPU» на доступное ядро), `meminfo` (лимит памяти профиля), `stat`, `uptime`,
  `loadavg`, `version`, `sys/kernel/random/boot_id` — синтетические; `interrupts`, `softirqs`, `diskstats`,
  `partitions`, `swaps`, `devices`, `misc`, `vmstat`, `cgroups`, `crypto`, `filesystems` и др. закрыты;
- имя `user`, `HOME=/home/user`, проект `/workspace`, `TZ=UTC`, `LANG=C.UTF-8`, `PATH=/usr/local/bin:/usr/bin:/bin`
  плюс только каталоги инструментов из профиля; passwd, group, hosts, инструкции и служебные скрипты передаются
  через дескрипторы, без путей хоста в `mountinfo`.

Включить обычную среду (пути и локаль хоста, как раньше) — `neutral = false` в профиле. В нейтральной среде
абсолютные пути проекта внутри (`/workspace/...`) отличаются от путей на хосте: сборки, записывающие абсолютные
пути в файлы (venv, CMake), нужно пересобирать на хосте.

### 5.2. Что остаётся видимым

Это не файлы, а интерфейсы ядра; скрыть их без ВМ нельзя: `uname` (версия и сборка ядра, архитектура),
модель и возможности процессора (инструкция CPUID), объём ОЗУ, число процессов и uptime хоста (`sysinfo()`),
ёмкость и занятость диска проекта (`df`), число доступных ядер (`nproc`), источники монтирования в
`/proc/self/mountinfo` (каталог установки песочницы и рабочей папки, имя устройства, тип ФС), список установленных
программ и библиотек в `/usr`. Профили `codex`/`claude`, у которых инструменты лежат в `~` (`~/.nvm`, `~/.local/bin`),
показывают скелет этих путей, а с ним и имя пользователя; чтобы его не раскрывать, ставьте инструменты в
`/usr/local` или `/opt`. Для полной непрозрачности нужен контейнер с собственным образом (Docker-режим,
[WINDOWS.md](WINDOWS.md)) или виртуальная машина.

### 5.3. Изоляция между проектами

По умолчанию `home_scope = "profile"`: один `$HOME` на профиль, поэтому вход в агента делается один раз, но
история и транскрипты агента видны во всех проектах этого профиля. Для разных доверительных зон задайте
`home_scope = "workspace"` — у каждой рабочей папки свой `$HOME` (`home/<профиль>+<проект>`), вход в агента нужен
в каждой. Следы монтирования чужих проектов в постоянном `$HOME` удаляются перед запуском и после него.

## 6. Защита: угроза → мера

| Угроза | Чем закрыто |
|---|---|
| Увидеть процессы хоста | своё PID-пространство: видны 1–3 процесса песочницы |
| Утечка окружения хоста | `env -i` для bwrap; задание передаётся анонимным файлом; окружение агента — только явно переданное |
| Читать память процесса | seccomp: `ptrace`, `process_vm_*`, `process_madvise`, `kcmp`, `pidfd_getfd`; `/proc/PID/mem` чужих недоступен |
| Сигналы процессам хоста | PID-пространство + Landlock scope (ядро 6.12+) |
| Службы хоста | своё сетевое пространство; абстрактные unix-сокеты закрыты пространством и Landlock |
| Ввод в ваш терминал | `--new-session` + запрет `TIOCSTI`/`TIOCLINUX` в seccomp (без seccomp сессия принудительная) |
| Побег из песочницы | seccomp (~70 вызовов, 32-бит и x32 запрещены, вызовы новее таблицы — ENOSYS), запрет вложенных user namespace, capabilities сброшены, `no_new_privs` |
| Сетевые семейства | белый список: UNIX, IPv4, IPv6, netlink только маршрутизации (AF_PACKET, AF_VSOCK, AF_ALG, AF_BLUETOOTH и др. закрыты) |
| Писать вне проекта | набор смонтированных путей + Landlock (запись: проект, `$HOME`, `/tmp`, устройства) |
| Читать секреты | их нет в песочнице; `~/.ssh` и т. п. отклоняются, даже если `$HOME` — символическая ссылка; диски и профиль Windows в WSL отклоняются |
| Запустить команду на хосте через файлы проекта | раздел 6.1 |
| Сведения об оборудовании и пользователе | раздел 5.1 |
| Нагрузка на хост | cgroup (`memory_max`, `tasks_max`) при `systemd --user`, иначе `RLIMIT_NPROC` (ядро 5.14+); `/tmp` ограничен `tmp_size`; квот диска нет |
| Сеть наружу | выключена или CONNECT к доменам/портам профиля; имя хоста проверяется по синтаксису, непубличные адреса (в т. ч. встроенные IPv4: `::ffff:`, 6to4, Teredo, NAT64) запрещены |

### 6.1. Файлы, которые хост выполнит сам

Рабочая папка принадлежит агенту, но хост позже может исполнять её содержимое: `git status` запустит команду из
`core.fsmonitor` в `.git/config`, `git commit` — хук из `.git/hooks`, IDE — задачи из `.vscode`, direnv — `.envrc`,
MCP-клиент — `.mcp.json`. Это воспроизведено: агент записал `core.fsmonitor`, обычный `git status` на хосте выполнил команду.

Что делает песочница (`protect = true`, если проект не только для чтения):

1. До запуска находит существующие `.git/config`, `.git/hooks`, `.gitmodules`, `.vscode`, `.idea`, `.envrc`, `.mcp.json`,
   `.claude/{settings.json,settings.local.json,hooks,commands,agents}`, `.codex/config.toml`, такие же файлы во вложенных
   репозиториях и в `.git/modules`, плюс `protect_extra` — монтирует их внутрь **только для чтения**. Каталоги-предки
   монтируются сами на себя, поэтому `mv .git .git-old` и `rm -rf` защищённого каталога не проходят («Device or resource busy»).
2. После запуска сравнивает снимок и печатает **ВНИМАНИЕ** со списком новых и изменённых опасных файлов (конфигурация git с
   `fsmonitor`, `hooksPath`, `sshCommand`, `credential.helper`, алиасами `!…`, фильтрами и т. п.; новые хуки, указатели
   `gitdir`, задачи IDE). Тот же отчёт — по запросу: `sandbox audit ИМЯ`.

Ограничения: каталог `.git`, созданный агентом во время запуска (`git init`), не защищён при этом запуске, он
обнаруживается проверкой; в защищённом `.git/config` не пишутся `git config`/`git remote add` (используйте
`git -c user.name=… commit`, глобальный `~/.gitconfig` в HOME агента или `protect = false`). Прежде чем запускать
`git`, IDE и скрипты проекта на хосте, выполните `sandbox audit`; не переходите по символическим ссылкам из `workspaces`.

## 7. Профили

Файлы `profiles/*.toml` (внешний файл — `sandbox run /путь/p.toml ИМЯ`):

    description = "Описание"
    command = ["codex"]
    network = "allowlist"
    domains = ["api.openai.com", "*.openai.com"]
    ro = ["~/.nvm", "/opt/tool"]       # где лежит агент и его рантайм (несуществующие пропускаются)
    env_pass = ["OPENAI_API_KEY"]
    neutral = true

| Ключ | По умолчанию | Значение |
|---|---|---|
| `command` | `[]` | запускаемая команда; в `shell` — `bash` |
| `workdir_rw` | `true` | проект с записью; `--access read` делает его только для чтения |
| `ro`, `rw` | `[]` | дополнительные каталоги; `rw` — только внутри `workspaces` (иначе `--allow-outside`) |
| `network`, `domains`, `ports`, `allow_private_net` | `off`, `[]`, `[443]`, `false` | `off`, `allowlist` (CONNECT к доменам `*.example.com`), `on` и `allow_private_net = true` запрещены |
| `env_pass`, `env_set` | `[]`, `{}` | переменные хоста для передачи; свои значения |
| `persist_home`, `home_scope` | `true`, `"profile"` | постоянный `$HOME`; один на профиль или на каждую рабочую папку (`"workspace"`) |
| `neutral` | `false` (в встроенных `true`) | нейтральная среда (раздел 5.1) |
| `protect`, `protect_extra` | `true`, `[]` | защита файлов, исполняемых на хосте (раздел 6.1); дополнительные пути |
| `memory_max`, `tasks_max`, `tmp_size` | `"8G"`, `2048`, `"1G"` | лимиты: память (`512M`, `8G`, `infinity`, `50%`), число задач, размер `/tmp` |
| `new_session` | `true` | новая сессия терминала; без seccomp включается принудительно |
| `seccomp`, `landlock`, `landlock_required` | `true`, `true`, `false` | `landlock_required = true` запрещает запуск на ядре без Landlock |

Если агент не запускается с сообщением «вне песочницы», добавьте каталог установки в `ro`: `readlink -f "$(which codex)"`.
Скрипты-обёртки, указывающие в другой каталог (как `/usr/bin/claude` -> `/opt/claude-code`), требуют `ro` и для него.

## 8. Сеть

- `off` — сети нет (по умолчанию у `default`).
- `allowlist` — TCP CONNECT к доменам и портам профиля через прокси на хосте (обычно HTTPS, 443). Прокси не проверяет
  TLS и содержимое. Имя хоста проверяется по синтаксису, непубличные и multicast IP всегда отклоняются, соединение
  идёт по уже проверенному IP. Разрешения и отказы пишутся в журнал. IPv6-адреса принимаются в скобках.
- `allowlist` с `domains = ["*"]` — весь интернет, но локальная сеть и localhost закрыты.
- Сеть хоста (`on`, прежний `--unsafe-host-net`) и `allow_private_net = true` запрещены, включая прямой вызов сборщика.

Перед запуском агентского кода проверяется отдельное сетевое пространство и наличие только `lo`.
Внутри виден loopback самой песочницы; DNS и `hosts` синтетические. VPN-интерфейсы,
DNS-суффиксы и маршруты хоста не передаются. Интернет работает через `127.0.0.1:3128` →
Unix-сокет → доверенный CONNECT-прокси; он использует подключение хоста. Прокси должен
ответить на проверку готовности за 20 секунд, иначе запуск прекращается. Оба моста
обслуживают максимум 64 соединения каждый, буферы ограничены 64 КиБ на направление,
тайм-аут без движения данных — 300 секунд. У заголовка CONNECT общий предел 10 секунд.
Повторного DNS-разрешения после проверки IP нет; при неудаче пробуются остальные адреса.
Прокси не перехватывает TLS и не скрывает внешний IP от сервиса.

Программа, не использующая `HTTPS_PROXY`, сети не получит — это и есть защита. Сервер, запущенный агентом на
`localhost`, доступен только внутри песочницы: открыть его в браузере хоста нельзя.

## 9. Чего защита не даёт

- Агент свободно меняет **всё** в рабочей папке (кроме файлов раздела 6.1). Держите там копию (git), а не единственный экземпляр.
- Не запускайте на хосте файлы, созданные агентом, не прочитав их; перед `git`/IDE на хосте — `sandbox audit`.
- Данные уходят на разрешённые домены (сервис ИИ получает ваш код); сужайте `domains`. Ключи, переданные агенту, ему доступны.
- Остаются видимыми интерфейсы ядра (раздел 5.2). Это защита ядра Linux: неизвестная уязвимость ядра и побочные каналы
  процессора её обходят. Обновляйте ядро; для заведомо вредоносного кода нужна ВМ.
- Вывод агента идёт прямо в ваш терминал: управляющие последовательности терминала не фильтруются. Запускайте агентов в доверенном терминале.
- `--allow-sensitive`, `--allow-outside` и лишние `ro`/`rw` расширяют доступ. Профили, лаунчер, каталоги инструментов и владелец хоста считаются доверенными; подмену путей другим
  процессом того же пользователя во время запуска защита не исключает.
- Внешние MCP/SSH-инструменты агента могут иметь отдельные права; локальные ограничения их не охватывают.
- Инструкции агенту (раздел 11) задают поведение, но не принуждают модель на уровне ОС.

## 10. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `bwrap: setting up uid map: Permission denied`, `No permissions to create new namespace`, `Operation not permitted`, `loopback: Failed to create NETLINK_ROUTE socket` | user namespaces недоступны. Ubuntu 23.10+/24.04: `./install.sh --fix-apparmor` (профиль только для bwrap; не отключайте ограничение для всей системы). Debian: `sudo sysctl kernel.unprivileged_userns_clone=1`. `user.max_user_namespaces=0`: `sudo sysctl user.max_user_namespaces=15000`. WSL1: `wsl --set-version ДИСТРИБУТИВ 2`. Внутри контейнера или другой песочницы — запустите на хосте. `sandbox check` печатает подходящую подсказку |
| `bubblewrap (bwrap) не найден` | `./install.sh --install-deps` или пакет из раздела 2.1 |
| `X вне песочницы: добавьте его каталог в ro` | раздел 7: `ro = ["/opt/claude-code"]`, `~/.nvm`, `~/.volta`, `~/.npm-global` |
| `лимиты памяти не применены (нет systemd --user)` | предупреждение; число процессов ограничено `RLIMIT_NPROC`. WSL2: `[boot] systemd=true`. По SSH: `loginctl enable-linger` |
| Программа не выходит в сеть | не использует `HTTPS_PROXY` (раздел 8) либо домен не в `domains`: `sandbox log` |
| TLS: `unable to get local issuer certificate` (Fedora, openSUSE) | монтируются `/etc/ssl`, `/etc/pki`, `/etc/ca-certificates`, `/etc/crypto-policies`, `/var/lib/ca-certificates`; нестандартное расположение — добавьте в `ro` (на этих дистрибутивах не проверялось) |
| `could not write config file .git/config: Device or resource busy` | защита раздела 6.1; `git -c user.name=… -c user.email=… commit`, `git config --global` в HOME агента или `protect = false` |
| `ВНИМАНИЕ: в рабочей папке файлы, которые хост может выполнить сам` | проверьте перечисленные файлы глазами, неизвестное удалите; `sandbox audit ИМЯ` повторит отчёт |
| Просит подтверждение снова | изменился профиль или версия песочницы: подтверждение привязано к хешу конфигурации |
| `Python 3.8+`, `ModuleNotFoundError: tomlmini/guard/neutral` | старый Python или неполная копия: `./install.sh --python python3.12`; копируйте каталог целиком |
| Ctrl-C закрыл всю песочницу | так задумано (раздел 4); нужен интерактивный Ctrl-C в оболочке — запускайте в профиле `new_session = false` (допустимо только с seccomp) |
| `sandbox: команда не найдена` | `~/.local/bin` не в `PATH`: `./install.sh --add-path` или добавьте строку в `~/.profile` |

## 11. Инструкции агенту и отчёт об исправлениях

`AGENT_POLICY.md` запрещает постороннюю диагностику процессов, интерфейсов, VPN, маршрутов и служб. При ошибке сети
агент фиксирует её текст и продолжает доступные проверки проекта; настройки изоляции разбирает владелец.

При каждом запуске файл монтируется только для чтения в `/run/sandbox/AGENT_POLICY.md`, `$HOME/.codex/AGENTS.override.md`
и `$HOME/.claude/CLAUDE.md`; `CODEX_HOME` и `CLAUDE_CONFIG_DIR` указывают на этот HOME. `new` создаёт проектные
`AGENTS.md` и `CLAUDE.md`, если копируемый проект их не содержит; инструкции проекта сохраняются. Инструкции задают
ожидаемое поведение, а не принуждают модель; проектные переопределения и настройки клиента влияют на их загрузку.

Отчёт агента содержит проблему, причину, затронутые файлы, исправление, команды проверок и результаты, а также всё
непроверенное. Шаблон — [REPORT_TEMPLATE.md](REPORT_TEMPLATE.md). Формат инструкций Codex сверялся с
[документацией OpenAI](https://learn.chatgpt.com/docs/agent-configuration/agents-md), Claude — с [Claude Code Docs](https://code.claude.com/docs/en/memory).

## 12. Проверки

    cd ~/sandbox
    python3 -m unittest discover -s tests -v      # 91 тест: песочница не нужна, хост не обследуется
    sandbox check && sandbox selftest default     # окружение и 33 живые атаки изнутри (codex, claude — аналогично)

Тесты проверяют разбор TOML, защиту файлов, нейтральную среду, прокси (разбор адреса, встроенные IPv4, экранирование
журнала), пути (симлинк `$HOME`, диски Windows), сборку аргументов bwrap в обоих режимах, ожидание дочернего процесса
и фильтр seccomp на собственном дочернем процессе. `selftest` подтверждает только проверенные сценарии и не доказывает
отсутствие других уязвимостей. На Windows (WSL, Docker) тесты имитируют внешние программы; интеграционную приёмку
на целевой машине описывает [WINDOWS.md](WINDOWS.md).
