# Терминальный рабочий стол AI Sandbox

[English](TUI.en.md) · [Назад к назначению проекта](README.md)

TUI работает в обычном терминале Linux, WSL2 и Windows. Современный экран построен на
виджетах Textual/Rich: слева размещены настройки и кнопки, справа — большая сезонная
карточка, таблица состояния модулей, события и журнал. Пиксельная сцена анимируется
лёгкими кадрами, без фоновых процессов. Для современного экрана нужны Python 3.10+ и
пакеты из `requirements-tui.txt` (Textual, Rich, Loguru, openpyxl). На Linux/WSL и
Windows для запуска используется один и тот же подкомандный интерфейс — `tui`, `check`,
`new` и остальные команды; отличаются только имена файлов запуска.

```bash
# Linux / WSL2: стабильная отдельная среда, чтобы не менять системный Python
python3 -m venv "$HOME/sandbox/.venv"   # Python 3.10+
"$HOME/sandbox/.venv/bin/python" -m pip install -r requirements-tui.txt
./start.sh tui
```

На Windows из распакованной папки:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-tui.txt
start.cmd tui
```

Если Textual не установлен, запускается облегчённый экран и показывается подсказка по
установке зависимостей. Нажмите цифру `0`–`8` прямо на клавиатуре — Enter не нужен;
Textual также поддерживает мышь, Tab и Enter. `Esc` или `q` закрывает TUI. Сезон
выбирается по календарю или в списке слева. Кнопка «Сохранить отчёт XLSX» создаёт
таблицу с проверками комплекта и выбранными настройками в `state/reports/`.

```text
Linux:    ./start.sh tui                      # также: ./start.sh check, ./start.sh new ...
Windows:  start.cmd tui                       # также: start.cmd check, start.cmd new ...
GUI:      start.cmd gui                       # прежнее графическое окно
```

Список существующих проектов — вверху левой панели, в поле «Существующий проект».
Выберите проект там мышью или клавишами. `[1]` только обновляет список. Чтобы начать
новый проект, введите имя в поле «Новый проект» и нажмите `[2]`. Папку-источник
можно не указывать: тогда создастся пустой проект; если указать — песочница подготовит
проект из этой папки и исходник не изменит. Создание автоматически установит навыки для Claude
и Codex. В правой сводке отображается выбранный проект и следующий шаг.

После выбора проекта настройте агента и доступ в левой панели. `[3]` вручную устанавливает
навыки Claude/Codex, `[4]` проверяет комплект, `[5]` запускает самотест изоляции, `[6]`
запускает агента, `[7]` тестирует проект внутри песочницы, `[8]` сохраняет XLSX-отчёт.
На Windows режим (`WSL 2`, Docker или отдельный пользователь) выбирается в поле сверху;
настройки адаптера и пользователя Windows находятся ниже. В WSL список читается из
выбранного дистрибутива, а в Docker и Linux — из папки проектов соответствующего режима.

Загрузка проверяет наличие и синтаксис собственных модулей, локальные правила,
TOML-профили и отсутствие в них опасных сетевых параметров. В ZIP для Windows также
сравниваются хеши программных файлов с локальным `SHA256.json`. Это **проверка
целостности комплекта**, не доказательство изоляции: список хешей не является
криптографической подписью. При ошибке программы TUI не предлагает запускать агента.
Кнопка `[5]` запускает `selftest` выбранного профиля; проверка защиты выполняется только
в предусмотренной изолированной среде и на собственных фикстурах. Кнопка `[4]` проверяет
окружение отдельно.
При запрете namespaces результат будет ошибкой или SKIP, а не успехом.

Кнопка `[3]` добавляет два текстовых навыка в копию выбранного проекта:
`.agents/skills/` для Codex и `.claude/skills/` для Claude. Они помогают разбирать
ошибку, выполнять тесты и писать отчёт в рамках `AGENT_POLICY.md`. Внешние каталоги
навыков и ключи пользователя не просматриваются. Существующие навыки проекта не
перезаписываются; ссылка или изменённый файл дают отказ. Новому проекту TUI предлагает
их сразу после создания. Навыки являются инструкциями, а границу доступа задаёт ОС.

Кнопка `[7]` запускает найденную по файлам проекта стандартную команду тестов
**через sandbox с выключенной сетью**. На Windows это доступно для WSL2 и Docker.
В режиме `user` проектные тесты можно запустить вручную через CLI с абсолютным путём
к установленному `.exe`; пункт `5` всегда доступен для проверки самой защиты.
Вывод тестов показывается непосредственно в терминале вместе с кодом завершения.

При установленных зависимостях предпросмотр откроет такой же виджетный экран, но
оставит действия выключенными. В неинтерактивном терминале команда выведет статичный
макет:

```bash
python3 sandbox.py tui --preview linux --season summer
python3 windows.py tui --preview windows --season summer
```

Демонстрация содержит условные статусы. Это внешний вид Windows TUI, запущенный здесь
как эмуляция; реальная работа WSL/Docker/Win32 проверяется на Windows отдельно.
